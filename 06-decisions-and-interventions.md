# 06 — Decision Playbooks and Business Value

The original report recommended learning support, preventive maintenance and targeted administrative follow-up. This page turns those directions into **proposed operating decisions**, not claims that programmes were launched.

## 1. Faculty — course support review

| Item | Proposed design |
|---|---|
| Trigger | A course persistently falls below a defined, agreed GPA or pass-rate benchmark across a sufficient eligible cohort. |
| Decision owner | Faculty lead with learning-support staff. |
| First action | Check grading standards, assessment mix, attendance completeness, class composition and course support coverage. |
| Next action | Pilot an accessible study-support intervention only after the problem is established. |
| Leading indicators | Attendance completeness, support take-up, contact reach and response. |
| Outcome indicators | Subsequent pass rate, learning progress, retention and feedback. |
| Validation | Compare with a suitable reference group/previous cohort; review confounding before causal claims. |

## 2. Facilities — overdue work-order triage

| Item | Proposed design |
|---|---|
| Trigger | Priority 4–5 work order past its agreed due date, or a rising overdue rate for a campus/work type. |
| Decision owner | Facilities operations lead. |
| First action | Reconcile status, assigned contractor, scope changes and safety implications; verify whether completion is simply unrecorded. |
| Next action | Allocate available capacity by safety/impact; pilot a weekly overdue review queue. |
| Leading indicators | Unassigned backlog, average age of open cases, work-order updates and SLA breaches. |
| Outcome indicators | Validated overdue rate, completion time, repeat faults, satisfaction and cost per resolved case. |
| Validation | Pre/post pilot with comparable work types and stable definitions; monitor unintended backlog displacement. |

## 3. Administration — inclusive support pathway review

| Item | Proposed design |
|---|---|
| Trigger | A valid observed *current* support flag or unexpectedly low participation among otherwise eligible students, after data checks. |
| Decision owner | Student support / academic advising team. |
| First action | Verify whether the flag is current and what data was available when; assess resource constraints and support eligibility. |
| Next action | Offer opt-in, accessible support to students meeting transparent needs-based criteria; monitor uptake. |
| Leading indicators | Offer coverage, service uptake, time to contact, voluntary engagement. |
| Outcome indicators | Future progress, retention and student-reported usefulness. |
| Validation | Privacy/fairness assessment and an appropriate evaluation design; do not infer ability from nationality or recruitment channel alone. |

## Proposed value framework

| Value dimension | Candidate KPI | How to substantiate it |
|---|---|---|
| Better prioritisation | Time from alert to triage decision | Collect pre-pilot and post-pilot process timestamps |
| Service reliability | Overdue high-priority work orders | Verify a fixed snapshot definition and baseline |
| Student experience | Useful support uptake and satisfaction | Consistent survey design and accessible participation |
| Cost stewardship | Cost per resolved relevant case | Costs must include the actual workload/resource basis |
| Trustworthy decisions | % dashboards with passing data checks | Automated validation log and sign-off |

**No measured savings, retention uplift or grade improvement is claimed.** Any value estimate would require assumptions, baseline collection, pilot scope and measured counterfactuals.
